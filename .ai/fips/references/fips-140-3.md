# FIPS 140-3 Reference Index

Created: 2026-06-10

Purpose: foundation reference set for researching and implementing FIPS 140-3 support in Keycloak.

## Source Policy

Only official NIST, CSRC, or NVLpubs government-hosted sources are indexed here. The FIPS 140-3 standard references ISO/IEC 19790 and ISO/IEC 24759; those ISO documents are not downloaded here because they are licensed ISO publications rather than freely hosted NIST/government PDFs. The official CSRC FIPS 140-3 standards page documents that dependency and the NIST request process for access.

## Local Layout

- Source manifest: [sources.tsv](sources.tsv)
- PDF checksum manifest: [sha256sums.txt](sha256sums.txt)
- Download and text extraction helper: [download_references.sh](download_references.sh)
- FIPS 140-3 PDFs and extracted text: [fips-140-3/](fips-140-3/)
- Shared algorithm, cipher, key management, random number, signature, KEM, and TLS references: [algorithms/](algorithms/)

The downloader creates one `.pdf` and one `.txt` file for every manifest row. The `.txt` files are produced with `pdftotext -layout` so Codex and Claude can read them without needing PDF parsing.

Download status in this checkout: complete. The manifest contains 48 official NIST/CSRC/NVLpubs PDFs, and this directory contains matching `.txt` extractions for all 48 entries.

## How To Use This Index

Start with FIPS 140-3, then the SP 800-140 series:

- SP 800-140 is the derived test requirement layer.
- SP 800-140A and SP 800-140B define documentation and security policy expectations.
- SP 800-140C is the key document for approved security functions.
- SP 800-140D covers approved sensitive parameter generation and establishment methods.
- SP 800-140E covers approved authentication mechanisms.
- SP 800-140F covers non-invasive attack mitigation test metrics.
- The FIPS 140-3 Implementation Guidance is the operational clarification source. The downloaded IG states `Last Update: April 16, 2026`.

For Keycloak and Java provider research, pair SP 800-140C and SP 800-140D with the shared algorithm references below, especially SP 800-52 Rev. 2 for TLS, SP 800-131A Rev. 2 for algorithm/key-size transitions, SP 800-57 for security strengths, SP 800-90 series for entropy/DRBG behavior, and SP 800-38 series for AES modes.

## Citation Requirement For Algorithm Inventory

When assembling supported ciphers, cipher suites, encryption algorithms, signatures, MACs, KDFs, random number generators, or key establishment mechanisms, every row must include:

- The exact algorithm or suite name as observed in Keycloak, Java, JSSE, or Bouncy Castle.
- The official NIST/CSRC document that mentions or governs it.
- The section, annex item, table, or implementation guidance paragraph where it is mentioned.
- A local text citation pointing at the extracted `.txt` file and line number where practical.
- A short status note such as `approved`, `allowed with restrictions`, `deprecated`, `disallowed`, `non-approved`, or `needs confirmation`.

Do not rely on algorithm names alone. For example, `AES/GCM/NoPadding` should cite both an observed provider name and the governing NIST text, such as SP 800-140C plus SP 800-38D; a TLS suite should cite SP 800-52 Rev. 2 and the precise table or paragraph covering that suite.

Recommended inventory columns:
